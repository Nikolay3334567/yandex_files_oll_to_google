# Яндекс Диск → Google Drive

Программа для Windows с веб-интерфейсом. Переносит **все** файлы с Яндекс Диска, включая раздел «Фото»
(безлимитную автозагрузку с телефона), на Google Drive напрямую: файлы идут потоком Яндекс → Google
и не сохраняются на ваш компьютер. Рассчитана на сотни
гигабайт и десятки тысяч фото и видео.

## Запуск

1. Установите [Python 3.10+](https://www.python.org/downloads/). При установке отметьте «Add python.exe to PATH».
2. Дважды щёлкните `run.bat`. При первом запуске он сам создаст окружение и поставит зависимость (`requests`).
3. Откроется браузер с адресом `http://127.0.0.1:8765/`. **Чёрное окно не закрывайте**: в нём работает перенос.

Чтобы собрать один `YandexToGoogle.exe`, запустите `build_exe.bat`. Готовый файл появится в `dist\`.

Настройки, прогресс и журнал хранятся в папке `data\` рядом с программой.

## Подключение

### Яндекс Диск
1. Откройте <https://oauth.yandex.ru/client/new> и создайте приложение:
   - платформа «Веб-сервисы»;
   - Redirect URI: `https://oauth.yandex.ru/verification_code`;
   - доступ: **Яндекс Диск REST API → «Чтение всего Диска»**.
2. Вставьте ClientID в программе и нажмите «Получить токен». Скопируйте показанный токен в поле и нажмите
   «Сохранить и проверить». Программа покажет владельца, занятое место и отдельно скажет, видны ли через
   API весь Диск и раздел безлимитных фото.

### Раздел «Фото» (автозагрузка с телефона)
Фото из безлимитной автозагрузки видны только в разделе «Фото», и официальный API Яндекса их не отдаёт
([подтверждение](https://github.com/ivknv/yadisk/issues/36)). Веб-версия Диска получает их так:

* `POST disk.yandex.ru/models-v2?m=mpfs/list` с путём `/photounlim` — **плоский список всех файлов раздела**
  постранично, с размером и MD5;
* `POST …/models-v2?m=mpfs/url` — прямая ссылка на оригинал файла, как у кнопки «Скачать».

Программа делает то же самое по кукам вашего входа (так же работает открытый проект
[yadisk_backup](https://github.com/PXSYS13/yadisk_backup)). Способ неофициальный: Яндекс может его изменить.

1. Поставьте расширение **Cookie-Editor** для Chrome, Яндекс.Браузера, Edge или Firefox.
2. Откройте <https://disk.yandex.ru/client/photo>.
3. В расширении выберите **Export → Export as JSON**, вставьте результат в блок «3. Раздел «Фото»» и нажмите
   «Сохранить и проверить».

Куки живут от нескольких дней до нескольких недель. Когда они устареют, на паузу встанет только раздел «Фото»,
остальные файлы продолжат переноситься. Обновите куки и нажмите «Старт».

### Google Drive
1. Создайте проект в [Google Cloud Console](https://console.cloud.google.com/) и включите **Google Drive API**.
2. На экране согласия OAuth (OAuth consent screen / Google Auth Platform) выберите тип *External* и добавьте
   себя в тестовые пользователи. Затем нажмите **Publish app → In production**. Если оставить режим *Testing*,
   Google будет отзывать токен каждые 7 дней.
3. Credentials → Create credentials → OAuth client ID → тип **Desktop app**. Скопируйте Client ID и secret в программу.
4. Нажмите «Войти в Google». На предупреждение «Приложение не проверено» ответьте «Дополнительно → Перейти».
   Это ваше собственное приложение.

Программа просит только область `drive.file`. Она видит лишь то, что создала сама, остальной Drive ей недоступен.

> **Место на Google.** Бесплатно дают 15 ГБ. Для 700 ГБ – 1 ТБ нужен тариф Google One на 2 ТБ.
> Когда место кончится, программа сама встанет на паузу и напишет причину.

## Как пользоваться

1. **«Получить список».** Яндекс отдаёт готовый плоский список: «Файлы» — официальным API
   (`/v1/disk/resources/files`), раздел «Фото» — через `mpfs/list`. Ничего не скачивается, только имена,
   размеры и MD5. Получение можно прервать и продолжить.
2. **«Старт».** Можно нажимать сразу, не дожидаясь конца списка. Каждый файл идёт потоком:
   Яндекс → память → Google. На диск компьютера ничего не пишется.
   * Файл до 32 МБ (это почти все фото) скачивается в память, **MD5 сверяется с Яндексом до загрузки**
     и заливается в Google одним запросом.
   * Файл больше 32 МБ (видео) заливается кусками по 32 МБ, и после каждого куска место запоминается.
     После сбоя или перезапуска загрузка продолжается с последнего куска, который подтвердил Google.
   * Файл получает статус «Готово», только когда Google вернул **тот же размер и MD5**, что на Яндексе.
3. **Структура на Drive.** `Yandex Disk/<те же папки, что на Яндексе>`. Раздел «Фото» раскладывается в
   `Yandex Disk/Фото (безлимит)/<год>/<год-месяц>/`.
4. **«Полная сверка с Google Drive».** Перечитывает с Google размер и MD5 каждого файла. Пропавшие и
   несовпавшие файлы снова встают в очередь. **«Отчёт (CSV)»** — таблица всех файлов: путь, размер, MD5,
   статус, отметка о сверке и ссылка на Drive.

### Скорость и бережность
* По умолчанию 4 параллельных потока, можно поставить до 16.
* К веб-версии Яндекса программа обращается не чаще ~8 запросов в секунду.
* На ответ «слишком часто» (429 или капча) от Яндекса или Google вся программа делает общую паузу,
  она растёт до часа.
* Перед загрузкой файла программа один раз запрашивает список файлов папки на Drive, а не делает отдельный
  запрос на каждый файл. Если такой файл уже есть (то же имя, размер и MD5), он не заливается повторно.
* Если ответ Google потерялся после того, как файл уже создан, программа сначала проверяет папку и только
  потом повторяет загрузку. Дубля не будет.

### Серверы Яндекса, которые не отвечают (с октября 2026)
Часть серверов хранения Яндекса сейчас молчит: не отвечает ни API, ни веб-версии. Файлы при этом не удалены.
Программа распознаёт такой сервер за 10 секунд и откладывает его файлы на 30 минут без траты попыток
(плитка «Ждут Яндекса»), а сама продолжает переносить остальное. Перенос не закончится, пока отложенные
файлы не будут перенесены. Не удаляйте ничего на Яндексе, пока всё не перенесено и не сверено.

### Что будет, если…

| Ситуация | Поведение |
|---|---|
| Программа упала, выключили компьютер или закрыли окно | При следующем запуске файлы «в работе» возвращаются в очередь, большой файл продолжается с места обрыва. Включите «При запуске сам продолжать», и перенос возобновится без нажатия «Старт». |
| Сеть моргнула или Яндекс оборвал скачивание | Программа повторяет с подтверждённого Google места, а маленький файл качает заново. |
| Неверный или просроченный токен Яндекса или Google | Перенос встаёт на паузу с понятной причиной, попытки не тратятся. |
| Устарели куки | На паузу встаёт только раздел «Фото», остальное продолжается. |
| Лимит Google (около 750 ГБ загрузки в сутки на аккаунт) | Общая пауза с нарастающей задержкой, потом программа продолжает сама. |
| MD5 или размер не совпали | Файл удаляется с Drive и загружается заново. |
| Файл не перенёсся 6 раз подряд | Статус «Ошибка», это видно в таблице. Кнопка «Повторить» вернёт его в очередь. |

### Удалил на Drive, хочу заново
* **«Полная сверка с Google Drive».** Всё, что вы удалили на Drive или убрали в корзину, снова встанет
  в очередь. Остальное не трогается.
* **«Начать перенос заново».** Все файлы снова попадают в очередь. Если включено «Не заливать повторно»,
  файлы, которые уже лежат на Drive с тем же именем и MD5, пропускаются, и дублей не будет.
* **«Очистить базу полностью».** Программа забывает всё, после этого нужно пересканировать Диск.
  Файлы на Drive не удаляются.
* В таблице «Файлы» можно повторить, пропустить или перезалить отдельный файл.

## Настройки
* **Потоков**: по умолчанию 3. Для мелких фото можно поставить 4–6, для больших видео достаточно 2–3.
* **Размер куска**: по умолчанию 32 МБ. Файлы меньше куска заливаются одним запросом. У больших место
  загрузки запоминается после каждого куска, поэтому при обрыве теряется не больше одного куска.
* **Способ сканирования**: «Плоский список» работает быстро. «Обход папок» — запасной вариант на случай,
  если плоский список у Яндекса сбоит.

## Проверка без настоящих аккаунтов
`python tests/test_e2e.py` запускает программу против имитации API Яндекса (официального и веб-версии)
и Google. Что проверяется:
* сбои: обрывы скачивания, случайные 503, процесс убивается посреди большого файла;
* докачка после перезапуска;
* устаревшие и рабочие куки;
* «молчащий» сервер хранения: файл откладывается, потом переносится сам;
* потерянные ответы Google без дублей;
* сверка после удаления файла на Drive и повторный полный прогон без дублей;
* совпадение MD5 каждого файла.

## Безопасность
Интерфейс слушает только `127.0.0.1`. Токены и куки хранятся открытым текстом в `data\settings.json` на вашем
компьютере, поэтому никому не передавайте эту папку.
