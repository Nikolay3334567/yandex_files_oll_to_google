# Яндекс Диск → Google Drive

Программа для Windows с веб-интерфейсом. Переносит **все** файлы с Яндекс Диска на Google Drive
напрямую, через API: файлы идут потоком и не сохраняются на ваш компьютер. Рассчитана на сотни
гигабайт и десятки тысяч фото и видео.

## Запуск

1. Установите [Python 3.10+](https://www.python.org/downloads/). При установке отметьте «Add python.exe to PATH».
2. Дважды щёлкните `run.bat`. При первом запуске он сам создаст окружение и поставит зависимость (`requests`).
3. Откроется браузер с адресом `http://127.0.0.1:8765/`. **Чёрное окно не закрывайте**: в нём работает перенос.

Чтобы собрать один `YandexToGoogle.exe`, запустите `build_exe.bat`. Готовый файл появится в `dist\`.

Настройки, прогресс и журнал хранятся в папке `data\` рядом с программой.

## Подключение

### Яндекс Диск
1. Откройте <https://oauth.yandex.ru/client/new> и создайте приложение:
   - платформа «Веб-сервисы»;
   - Redirect URI: `https://oauth.yandex.ru/verification_code`;
   - доступ: **Яндекс Диск REST API → «Чтение всего Диска»**.
2. Вставьте ClientID в программе и нажмите «Получить токен». Скопируйте показанный токен в поле и нажмите
   «Сохранить и проверить». Программа покажет владельца, занятое место и отдельно скажет, видны ли через
   API весь Диск и раздел безлимитных фото.

### Google Drive
1. Создайте проект в [Google Cloud Console](https://console.cloud.google.com/) и включите **Google Drive API**.
2. На экране согласия OAuth (OAuth consent screen / Google Auth Platform) выберите тип *External* и добавьте
   себя в тестовые пользователи. Затем нажмите **Publish app → In production**. Если оставить режим *Testing*,
   Google будет отзывать токен каждые 7 дней.
3. Credentials → Create credentials → OAuth client ID → тип **Desktop app**. Скопируйте Client ID и secret в программу.
4. Нажмите «Войти в Google». На предупреждение «Приложение не проверено» ответьте «Дополнительно → Перейти».
   Это ваше собственное приложение.

Программа просит только область `drive.file`. Она видит лишь то, что создала сама, остальной Drive ей недоступен.

> **Место на Google.** Бесплатно дают 15 ГБ. Для 700 ГБ – 1 ТБ нужен тариф Google One на 2 ТБ.
> Когда место кончится, программа сама встанет на паузу и напишет причину.

## Как пользоваться

1. Нажмите **«Сканировать»**. Программа запросит у Яндекса плоский список всех файлов Диска
   (`/v1/disk/resources/files`) и затем раздел безлимитных фото (`photounlim:/`). Сканирование можно прервать
   и продолжить.
2. Нажмите **«Старт»**. Переносить можно, не дожидаясь конца сканирования. Сверху видны общий прогресс,
   скорость и оставшееся время. Ниже показан каждый файл в работе: путь, этап и сколько байт передано.
3. Структура на Drive: `Yandex Disk/<те же папки, что на Яндексе>`. Безлимитные фото лежат в
   `Yandex Disk/Фото (безлимит)/<год>/<год-месяц>/`.

### Что будет, если…

| Ситуация | Поведение |
|---|---|
| Программа упала, выключили компьютер или закрыли окно | При следующем запуске файлы «в работе» возвращаются в очередь. Большой файл **продолжается с места обрыва**: Google хранит сессию загрузки около недели. Включите «При запуске сам продолжать», и перенос возобновится без нажатия «Старт». |
| Сеть моргнула или Яндекс оборвал скачивание | Программа спрашивает у Google, сколько байт он уже принял, и продолжает с этого места. |
| Неверный или просроченный токен | Перенос встаёт на паузу с понятной причиной, попытки по файлам не сжигаются. |
| Лимит Google (около 750 ГБ загрузки в сутки на аккаунт) | Общая пауза с нарастающей задержкой до 1 часа, потом программа продолжает сама. При 1 ТБ этот лимит почти наверняка сработает. |
| Файл не скачался 6 раз подряд | Файл получает статус «Ошибка» и не мешает остальным. Кнопка «Повторить файлы с ошибками» вернёт его в очередь. |
| После загрузки MD5 не совпал с Яндексом | Файл удаляется с Drive и загружается заново. |

### Удалил на Drive, хочу заново
* **«Сверить с Google Drive».** Всё, что вы удалили на Drive или убрали в корзину, снова встанет в очередь.
  Остальное не трогается.
* **«Начать перенос заново».** Все файлы снова попадают в очередь. Если включено «Не заливать повторно»,
  файлы, которые уже лежат на Drive с тем же именем и MD5, пропускаются, и дублей не будет.
* **«Очистить базу полностью».** Программа забывает всё, после этого нужно пересканировать Диск.
  Файлы на Drive не удаляются.
* В таблице «Файлы» можно повторить, пропустить или перезалить отдельный файл.

## Про раздел «Фото»

* Всё, что видно в «Фото» и лежит в папках Диска (например, в «Фотокамера» при автозагрузке с телефона),
  возвращает метод `/v1/disk/resources/files`. Это полный плоский список всех файлов Диска, даже без обхода папок.
* Фото из **безлимита** (`photounlim:/`) в официальной документации REST API почти не описаны. Программа
  пробует читать их через `/v1/disk/resources?path=photounlim:/`. Работает ли это на вашем аккаунте, видно
  сразу после проверки токена: строка «Раздел безлимитных фото: доступен / недоступен».
  Если недоступен, перенесите безлимитные фото в обычную папку Диска через веб-интерфейс Яндекса
  (на это нужно свободное место) и пересканируйте.

## Настройки
* **Потоков**: по умолчанию 3. Для мелких фото можно поставить 4–6, для больших видео достаточно 2–3.
* **Размер куска**: по умолчанию 32 МБ. Сессия загрузки сохраняется после каждого куска, поэтому при
  обрыве теряется не больше одного куска.
* **Способ сканирования**: «Плоский список» работает быстро. «Обход папок» — запасной вариант на случай,
  если плоский список у Яндекса сбоит.

## Проверка без настоящих аккаунтов
`python tests/test_e2e.py` запускает программу против имитации API Яндекса и Google. В тесте обрываются
скачивания, сервер случайно отвечает 503, процесс убивается посреди большого файла. Затем тест проверяет
докачку, сверку после удаления файла на Drive, повторный полный прогон без дублей и совпадение MD5
каждого файла.

## Безопасность
Интерфейс слушает только `127.0.0.1`. Токены хранятся открытым текстом в `data\settings.json` на вашем
компьютере, поэтому никому не передавайте эту папку.
